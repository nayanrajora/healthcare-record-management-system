How To Demonstrate This Feature in Your Viva

In traditional relational healthcare databases, a database administrator or malicious actor can open SQLite/MySQL and modify a patient's prescription or diagnosis without leaving any trace. In this system, because each clinical entry was hashed with SHA-256 and chained into a blockchain block, any direct SQL modification produces an avalanche effect mismatch that is immediately caught by the verification engine!

Simulation 1: Alter Database Record

Simulates an unauthorized direct SQL update to Record #1 (Version 1)'s prescription (e.g., secretly altering Amlodipine to an unauthorized dosage) without going through the blockchain logic.

Simulation 2: Break Hash Pointer

Simulates modifying the previous_hash pointer of Block #2. This demonstrates how cryptographic chaining detects any alteration to the ledger history itself.

Restoration: Revert to Authentic State

Re-seeds the pristine demonstration medical records and recomputes the valid blockchain hash chain, returning the system to 100% verified status.

Demonstration Script for Faculty Evaluators
  1. Navigate to Integrity Audit: Show that the initial system is 100% Verified (green shield).
  2. Return here and click Simulate Record Tampering: Explain that this simulates an attacker secretly modifying clinical data directly in SQLite.
  3. Click Check Verification Results: Show the examiner that the system instantly detects the exact record ID and displays the cryptographic hash mismatch in red.
  4. Click Restore Authentic Demo Data and re-verify: Show the green shield restored!
